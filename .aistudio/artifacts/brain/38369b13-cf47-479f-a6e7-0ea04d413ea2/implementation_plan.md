# План реализации обновления negai (Pre-release)

## 1. GitHub Actions: статус Pre-release и постоянный сертификат подписи APK
* **Публикация как Pre-release**:
  * В `.github/workflows/build-apk.yml` обновить шаг `Create New Patch or Version Release`: заменить флаг `--latest` на `--prerelease` в команде `gh release create`, а также отметить выпуск как предварительный в описании релиза.
* **Исправление сертификата подписи (обновление поверх установленной версии без ошибки конфликта подписи)**:
  * Причина проблемы: если в репозитории GitHub отсутствовал файл `debug.keystore.base64` и не был задан секрет `SIGNING_KEYSTORE_BASE64`, workflow выполнял `keytool -genkeypair`, создавая **новый случайный сертификат** при каждой сборке.
  * Решение: убрать генерацию случайного ключа `keytool -genkeypair` из `.github/workflows/build-apk.yml` и встроить фиксированный резервный Base64-слепок штатного ключа проекта (`debug.keystore.base64`), чтобы все сборки (и в AI Studio, и в GitHub Actions) всегда подписывались одним и тем же сертификатом.

## 2. Точное определение озвучки и субтитров в подробной информации о торренте
* **Причина ложного срабатывания «Субтитры»**:
  * Ранее регулярное выражение в `TorrentModels.kt` объединяло озвучку и субтитры в одно поле и не распознавало стандартные метки русской дорожки (`[RUS(int)]`, `[RUS(ext)]`, `[RUS]`, `ПМ`, `ПД`, `ЛМ`, `ЛД`, `ЛО`, `АП`, `Дубляж`, `Многоголосый`, `Двухголосый`, `Одноголосый`), но срабатывало на `+ Sub` / `JAP+Sub` в заголовке.
* **Изменения (`TorrentModels.kt`, `TorrentSearchService.kt`, `TorrServerSheets.kt`)**:
  * Разделить распознавание на два независимых списка: **Озвучка и перевод** (`voiceoverTags`) и **Субтитры** (`subtitleTags`).
  * Расширить парсер заголовков и описаний на стандартные теги озвучки (`RUS(int)`, `RUS(ext)`, `RUS`, `Dub`, `Дубляж`, `MVO`/`ПМ`/`ЛМ`, `DVO`/`ПД`/`ЛД`, `VO`/`ЛО`/`АП`, `Многоголосый`, `Двухголосый`, `Авторский`, а также студии озвучки).
  * Добавить чтение массива `"voices"` из ответов API JacRed и извлечение строк `Перевод:` / `Озвучка:` / `Аудио:` из HTML-описания раздачи при открытии карточки.
  * В карточке подробной информации о раздаче отображать **Озвучку** отдельно от **Субтитров** (и никогда не писать «Субтитры» в поле озвучки, если у раздачи есть звуковая дорожка/перевод).

## 3. Кнопка глав над таймлайном и список глав с таймингами
* **Чистая кнопка текущей главы (`PlayerScreen.kt`)**:
  * Убрать дополнительные кнопки переключения `⏮` и `⏭` рядом с кнопкой глав над полосой прокрутки (слева).
  * Оставить единую компактную пилюлю с иконкой и названием текущей главы (видимую только при наличии глав в файле), нажатие на которую сразу открывает список глав.
* **Список глав (`PlayerInterpolationAndChaptersSheets.kt`)**:
  * В окне списка глав убрать дублирующие верхние кнопки переключения и отображать для каждой главы её порядковый номер, название, **точный тайминг начала главы** (`00:00`, `01:30` и т.д.) и длительность, с мгновенным переходом к главе по нажатию.

## 4. Компактные полупрозрачные всплывающие меню плеера (65% непрозрачности) и уборка лишних индикаторов
* **Полупрозрачный компактный дизайн шторок и меню (`PlayerControlSheets.kt`, `PlayerExtrasSheet.kt`, `PlayerInterpolationAndChaptersSheets.kt`, `QuickActionsCustomizerSheet.kt`, `PlayerScreen.kt`)**:
  * Перевести все всплывающие окна/шторки плеера на компактный макет с полупрозрачным фоном **65% непрозрачности** (`containerColor = Color(0xFF0E131F).copy(alpha = 0.65f)`) и облегчённым затемнением вокруг (`scrimColor = Color.Black.copy(alpha = 0.18f)`), чтобы видео оставалось хорошо видимым.
  * Уменьшить размеры шрифтов заголовков, подзаголовков и элементов списков, сократить внутренние отступы (`padding`), высоту карточек и максимальную ширину всплывающих панелей.
* **Удаление индикатора частоты экрана из верхней панели плеера (`PlayerScreen.kt`)**:
  * Убрать плашку отображения герцовки экрана / статуса интерполятора (`player_hw_badge`, например `60Гц` / `MEMC • 120Гц`) из верхней панели плеера, так как этот функционал уже доступен через кнопку интерполятора.

## 5. Синхронизация видео и аудио + компенсация задержки Bluetooth (Игровой режим)
* **Удаление плашки задержки Bluetooth (`PlayerControlSheets.kt`)**:
  * Убрать бейдж отображения расчётной задержки Bluetooth (`-150 мс`) из заголовка шторки «Аудио и усиление».
* **Исправление работы компенсации и кнопки синхронизации (`PlayerEngine.kt`, `AudioDelayProcessor.kt`, `BluetoothAudioSyncController.kt`, `PlayerControlSheets.kt`)**:
  * Исправить ошибку в `PlayerEngine.startPlaylist`, где вызов `audioDelayProcessor.setDelayMs(0L)` после `recalculateEffectiveAudioDelay()` сбрасывал фактическую компенсацию задержки в `0 мс`.
  * Реализовать полноценный двусторонний сдвиг синхронизации в `MediaCodecAudioRenderer.getPositionUs()` и `AudioDelayProcessor` как для отрицательных значений (опережение звука / компенсация Bluetooth), так и для положительных значений (задержка звука), чтобы изменение сдвига немедленно сдвигало видео относительно аудио.
  * Сделать кнопку **«Синхронизировать аудиопоток с видео»** реально работающей: при нажатии она пересчитывает задержку активного аудиовыхода, сбрасывает накопившийся рассинхрон буферов `AudioDelayProcessor` и выполняет точную синхронизацию позиции дорожек.
  * Добавить в шторку аудио и настройки быстрые пресеты задержки для разных режимов наушников:
    * **Выкл / Провод (`0 мс`)**
    * **Игровой режим BT (`-45 мс`)**
    * **BT LE Audio (`-60 мс`)**
    * **Стандартный BT (`-150 мс`)**
    * плюс плавная ручная подстройка с шагом `±10 мс` / `±25 мс` / `±50 мс`.

## 6. Совместная работа Anime4K и интерполяции кадров (MEMC)
* **Автоматический переход Anime4K в быстрый режим (`PlayerModels.kt`, `Anime4KVideoSurface.kt`, `PlayerControlSheets.kt`, `PlayerInterpolationAndChaptersSheets.kt`)**:
  * При одновременном включении тяжелых режимов `Anime4K (CNN / CNNX)` и `Интерполяции кадров (MEMC)` многопроходный конвейер с промежуточными текстурами (`fboMid`, `fboUp`) создаёт чрезмерную нагрузку на GPU при 60–120 кадрах/с, вызывая пропуск кадров и срыв плавности интерполяции.
  * Добавить вычисление эффективного режима шейдера: когда активна интерполяция кадров (`interpolationMode != OFF`) и выбран многопроходный режим Anime4K (`ANIME4K_CNN` или `ANIME4K_CNNX`), GL-рендерер автоматически переключает шейдерный проход на однопроходный **`ANIME4K_FAST`**, сохраняя чёткость контуров и стабильные 60–120 FPS без перегрузки GPU.
  * В меню Anime4K и интерполяции отображать компактную подсказку об активной авто-оптимизации при их совместной работе.

* **Новая категория `SettingsCategory.DEVICE_INFO` (`PlayerModels.kt`, `SettingsTabScreen.kt`, `SettingsCategoryPages.kt`)**:
  * Добавить пункт **«Об устройстве и декодерах»** в список разделов настроек.
  * Отображать подробную техническую сводку:
