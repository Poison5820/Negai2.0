# negai: Высокая герцовка интерфейса (120 Гц), мгновенное появление кнопок плеера (100 мс) и динамическая Bluetooth-задержка (Gaming Mode)

План оптимизации плавности интерфейса, устранения задержек отображения элементов управления плеера и внедрения автоматической адаптации к задержке Bluetooth-аудиоустройств в реальном времени.

### User Review & Critical Decisions

> [!IMPORTANT]
> Ключевые решения согласованы на основе ответов пользователя:

- **Частота обновления экрана (Герцовка)**:
  - Везде в интерфейсе приложения (список папок, библиотека, настройки, диалоги) экран работает на максимальной поддерживаемой частоте устройства (90 / 120 / 144 Гц).
  - В плеере: во время воспроизведения видео с выключенным интерфейсом частота экрана подстраивается под частоту кадров видеопотока (LTPO 24/30/48/60 Гц) для экономии батареи и исключения дрожания кадров (judder).
  - При касании экрана или отображении элементов управления (HUD) плеер **мгновенно форсирует максимальную герцовку** (120 Гц), обеспечивая идеальную плавность анимаций.
- **Появление кнопок управления плеера**:
  - Устраняется фриз и просадка кадров при первом и повторных вызовах интерфейса плеера.
  - Переход выполняется за **100 мс** через легковесную анимацию прозрачности на уровне графических слоёв (`graphicsLayer { alpha = ... }`) без повторной тяжёлой рекомпозиции и перерасчёта макетов.
- **Динамическая задержка Bluetooth (Gaming Mode)**:
  - Убираются фиксированные ручные переключатели и профили.
  - Плеер автоматически считывает фактическую аппаратную задержку аудиоподсистемы Android через `AudioTrack.getLatency()` (HAL / Bluetooth A2DP / LE Audio buffer latency).
  - При включении игрового режима (Gaming Mode / Low Latency) на наушниках Android уменьшает размер аудиобуфера, и плеер сразу автоматически пересчитывает тайминги видео и субтитров без перезапуска трека.
  - В аудио-меню плеера отображается текущая аппаратно измеренная задержка в миллисекундах (например, `48 мс (Игровой режим)` или `142 мс (Стандартный)`).

### 1. Архитектурный анализ и причины текущих проблем

1. **Почему интерфейс папок и настройки работали в 60 Гц**:
   - `DisplayRefreshRateController.kt` применял `preferredDisplayModeId` / `preferredRefreshRate`, но `defaultSettings.highRefreshRateEnabled` либо сбрасывался в `false`, либо окно приложения не форсировало максимальный режим для не-видео экранов.
   - В `MainActivity.kt` при инициализации отсутствовал принудительный запрос максимальной частоты дисплея (`display.supportedModes.maxByOrNull { it.refreshRate }`).
2. **Почему плеер фризил при вызове кнопок**:
   - В `PlayerScreen.kt` при воспроизведении 24 fps видео дисплей работал на 24 Гц (или 48 Гц). Когда пользователь нажимал на экран, Compose запускал `AnimatedVisibility(visible = controlsVisible)` прямо на 24/48 Гц, что визуально воспринималось как резкий лаг.
   - Компоненты панели (`ThemedPlayerCenterTransport`, `ThemedPlayerSeekBar`, `PlayerQuickActionsBar`) каждый раз полностью пересоздавались и рекомпоновались при смене `controlsVisible`.
3. **Почему задержка Bluetooth была статичной**:
   - `BluetoothAudioSyncController.kt` использовал фиксированную таблицу констант (`-150L` для A2DP, `-60L` для LE Audio, `0L` для динамиков) без опроса реальной задержки от драйвера Android и наушников.

### 2. План реализации по компонентам

#### Этап 1: Высокая герцовка во всем приложении и динамический буст в плеере
- **`DisplayRefreshRateController.kt` & `MainActivity.kt`**:
  - Реализовать функцию `applyMaxRefreshRate(window)`: выбор режима дисплея с максимальной частотой (`maxSupportedHz`: 90 / 120 / 144 Гц) и установка `window.attributes.preferredRefreshRate = maxHz` (а на Android 11+ также `window.setFrameRate(maxHz, Surface.FRAME_RATE_COMPATIBILITY_DEFAULT)`).
  - В `MainActivity.onCreate()` и при возврате из плеера автоматически активировать режим максимальной герцовки для всех списков, папок и настроек.
- **Интеграция в `PlayerScreen.kt`**:
  - Состояние `controlsVisible`: при `controlsVisible == true` или при активном жесте касания моментально повышать целевую частоту окна до `maxSupportedHz`.
  - Только когда `controlsVisible == false` и воспроизведение стабилизировано — плавно возвращать экран к частоте видеопотока (LTPO).

#### Этап 2: Мгновенное появление кнопок плеера (100 мс без фризов)
- **`PlayerScreen.kt` & `PlayerControlsThemedComponents.kt`**:
  - Заменить тяжёлый блок пересоздания интерфейса на `animateFloatAsState(targetValue = if (controlsVisible) 1f else 0f, animationSpec = tween(durationMillis = 100))`.
  - Применять анимированную прозрачность через `Modifier.graphicsLayer { alpha = controlsAlpha }` и отключать `pointerInput` при `alpha == 0f`, избегая лишних проходов layout/measure.
  - Предварительно удерживать структуру HUD в композиции, чтобы при нажатии экран не тратил кадры на создание View-узлов.

#### Этап 3: Динамическое измерение Bluetooth-задержки (Gaming Mode)
- **`BluetoothAudioSyncController.kt`**:
  - Внедрить вызов системного метода HAL latency `AudioTrack.getLatency()` через рефлексию (стандартный скрытый метод Android, доступный на всех версиях AOSP), а также чтение смещения через `AudioTimestamp`.
  - Запустить периодический легковесный поллинг (раз в 1–2 секунды при активном Bluetooth-подключении), который фиксирует изменение задержки буфера (например, падение со 160 мс до 45–60 мс при включении игрового режима на наушниках).
  - Автоматически транслировать измеренную задержку в `MediaClock` плеера без участия пользователя.
- **`PlayerControlSheets.kt` (Меню звука)**:
  - Убрать статический селектор ручных профилей задержки.
  - Добавить карточку мониторинга реальной задержки: статус устройства, текущая измеренная задержка (в мс), бейдж режима низкой задержки / игрового режима.
  - Сохранить возможность тонкой пользовательской подстройки (слайдер ±500 мс), которая суммируется с аппаратно измеренным значением.

### 3. Верификация и тестирование

1. **Компиляция**: Запуск `compile_applet` для подтверждения целостности кодовой базы.
2. **Модульные и системные тесты**: Запуск `gradle :app:testDebugUnitTest` (включая Robolectric-тесты аудио-контроллера и расчёта герцовки).
3. **Проверка сценариев**:
   - Проверка переключения режимов экрана: библиотека/папки работают на максимуме герцовки;
   - Замер времени анимации появления кнопок плеера (100 мс, отсутствие пересоздания компонентов);
   - Проверка корректности считывания HAL-задержки и работы плеера при смене аудиовыходов (динамик, наушники, игровой режим).
